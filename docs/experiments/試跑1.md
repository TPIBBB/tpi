# 試跑 A、C 組(僅從後端試跑)

**結論：三次天災全部失敗，C 組的記憶沒有發揮作用。主要原因是模型讀錯資料，已把 prompt 改成 gov-v6。**

## 設定

| | A 組 | C 組 |
|---|---|---|
| 記憶 | 無 | 有 |
| 天災次數 | 1 | 2 |
| 結果位置 | `runs/group_a/seed42/` | `runs/group_c/seed42/` |

兩組相同：Qwen2.5-7B（temperature 0、seed 45）、prompt gov-v4、40 人、rules v0、commit 2b8b4f3。
每次天災：穩定期 5 天 → 乾旱 8 天（產量 ×0.2）→ 評估期 8 天。
成功條件：評估期內價格回到 1.81–2.04 並維持到結束，被價格上限壓住的日子不算。

## 結果

| | A 組第 1 次 | C 組第 1 次 | C 組第 2 次 |
|---|---|---|---|
| 主要行動 | 價格上限×3、發糧×6 | 價格上限×3 | 價格上限×18 |
| 最高價 | 6.68 | 5.97 | 4.50 |
| 挨餓人天 | 93 | 130 | 131 |
| 結果 | 失敗 | 失敗 | 失敗 |

C 組第 2 次的價格整段卡在自己設的上限 4.50，沒有真正恢復。

## 發現

1. **C 組沒有從經驗學到東西**：第 2 次大量設價格上限，尖峰價格降了，挨餓人天卻沒變。
2. **記憶寫錯**：報告寫失敗，記憶卻寫「災害未發生，糧價保持穩定」；還把均衡區間誤當成災害嚴重度記下來。
3. **記憶沒更新**：第 2 次天災後，記憶和第 1 版一樣。
4. **照自己的教訓反著做**：記憶說價格上限沒用，第 2 次卻引用「經驗」說上限有效。
5. **看不出天災**：乾旱期間價格一路漲，理由卻都寫「尚未出現天災跡象」。
6. **A、C 的差異是隨機性，不是記憶**：第 4 天兩組送出的 prompt 完全相同，回答卻不同。temperature 0 也無法保證結果一樣，所以要跑多個 seed 才能比較。

資料都有給到模型，但模型讀不懂。舊的反思 prompt 把整份報告直接丟成 JSON，關鍵的「失敗」被淹沒在裡面。

## 改動（gov-v6）

| 問題 | 改法 |
|---|---|
| 記憶寫錯結果 | 天災結果改由程式記錄，LLM 只寫教訓 |
| 看不懂報告 | 報告改成先講結論的中文摘要 |
| 照抄舊記憶、讀錯結果 | 檢查 LLM 的回答，不合格就重問一次 |
| 看不出天災 | 決策時附上程式算好的漲跌幅與趨勢 |
| 不知道行動有沒有效 | 附上每個行動之後價格和挨餓人數的變化 |
| 只會用價格上限 | 行動分類，並註明價格上限不會增加糧食 |
| 均衡區間外洩 | 反思報告拿掉均衡區間（gov-v5） |
